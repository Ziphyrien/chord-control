# 运行遥测

定期采集本机运行状态，供管理员在[状态页面](https://chord.zipawa.top)排查问题。插件页面可立即上报、查看最近报告；在控制中心暂停插件即可停止采集。

1.1.0 使用 Chord 0.86.1，需要主程序 0.4.6。Windows x64 采集器由 CI 编译，随签名插件归档分发。客户机使用应用自带的运行环境。

## 采集内容

- 计算机名、用户名、系统版本、运行时间和资源使用量。
- 主程序与插件版本、运行状态、调用指标和最近20条活动。
- 原生调用失败的插件、时间、API、系统错误码、进程身份、目标键和值名称。
- UAC 配置、指定进程的权限令牌，以及失败目标在采样时的 DACL 检查结果。

注册表事件保存目标名称，值内容留在业务插件中。身份文件保存在插件数据目录：清空身份会生成新的客户端 ID，克隆机器时应为每台设备生成独立身份。

## 模块职责

| 模块                | 职责                                  |
| ------------------- | ------------------------------------- |
| `src/worker.ts`     | 组装 Chord 服务与插件生命周期         |
| `src/reporter.ts`   | 定时采集、报告签名、上传和状态        |
| `src/connection.ts` | 远程采集请求与重连                    |
| `src/store.ts`      | 本地 Ed25519 身份和报告序号           |
| `src/windows.ts`    | 选择失败目标、启动采集器并验证结果    |
| `native/`           | UAC、进程令牌与注册表 DACL 的只读采集 |
| `ui/`               | 通过注入服务呈现插件状态              |

主程序的 `HostDiagnostics` 提供通用执行事实；各插件通过可选的 `PluginDiagnostics` 提供业务指标。接收端的存储、后台查询和部署见[服务说明](../../services/telemetry/README.md)。

## 周期和结果

默认每5分钟上报。失败后逐步退避，最长30分钟。后台“立即采集”通过客户端建立的连接请求新报告；离线时保留一个待处理请求，重连后执行。整次采集和上传的期限为30秒。

Windows 采集器最多检查3个进程和8个失败目标，限时10秒，输入上限32 KiB、输出上限64 KiB。暂停插件会取消采集和上传。单项读取失败会保留该项错误及其他成功结果。

原生失败历史在主程序内存中保留最近16条，并带有统计起点、累计数和丢弃数。重启后重新统计。进程通过 PID 和创建时间共同识别，创建时间使用 FILETIME 字符串。

DACL 检查反映采样时指定进程对目标键的权限。目标不存在时，可检查最近存在祖先的创建子键权限，结果单独标明实际检查路径和权限。原始失败原因仍需结合事件时间、策略状态和相关日志判断。原生采集协议、字段和测试命令见[采集器契约](native/src/contract.md)。

## 指标

| 字段                                       | 含义                                 |
| ------------------------------------------ | ------------------------------------ |
| `version / latestVersion`                  | 已安装与可用版本                     |
| `running / status / sourceStatus`          | 实际运行、本地选择与来源状态         |
| `attempts / succeeded / failed / inFlight` | 统计周期内的调用次数                 |
| `successRatio`                             | 已结束调用中的成功比例；无样本时为空 |
| `meanMs / maxMs / lastMs`                  | 平均、最大、最近调用耗时             |
| `since / lastSuccessAt / lastFailureAt`    | 统计起点与最近结果时间               |

调用指标衡量调用结果；业务效果由对应插件自报，例如学习权限的策略核验数量和通过比例。缺失数据和采集错误分别显示。
