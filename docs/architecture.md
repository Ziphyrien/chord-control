# 模块职责与依赖方向

前端只消费共享命令和快照协议。控制器应用层串行调度命令和检查周期，插件管理负责注册与更新事务，运行时负责 Chord facet 生命周期。构建脚本复用发布格式，不导入控制器实现。

| 模块                                    | 职责                                         | 主要依赖                         |
| --------------------------------------- | -------------------------------------------- | -------------------------------- |
| `shared/protocol.ts`                    | 跨进程命令、事件和数据类型                   | 无运行时依赖                     |
| `shared/plugin-format.ts`、`signing.ts` | 发布格式、路径规则、签名编码与校验           | Node 标准库                      |
| `src/main.ts`                           | 创建通信客户端并挂载界面                     | 前端装配入口                     |
| `src/lib/controller.ts`                 | Tauri IPC 请求关联、超时与订阅               | 共享协议、Tauri                  |
| `src/lib/session.svelte.ts`             | 界面会话状态与操作结果                       | 通信接口、桌面能力适配器         |
| `src/components/`                       | 插件列表、记录、设置表单、添加弹窗和插件页面 | 数据及回调属性                   |
| `controller/src/index.ts`               | 装配依赖、启动和退出                         | 控制器各适配器                   |
| `application.ts`、`queue.ts`            | 命令分发、串行队列、周期检查                 | 插件管理、UI 接口                |
| `plugin-manager.ts`                     | 注册、安装、恢复、目录差异和启停事务         | 配置仓储、归档接口、生命周期接口 |
| `config.ts`                             | 配置解析、迁移、持久化                       | 文件存储、共享格式               |
| `sources.ts`                            | 有界 HTTPS 下载和 ETag                       | 网络、哈希校验                   |
| `storage.ts`、`artifacts.ts`            | 原子写入、归档缓存、安全解压                 | 文件系统、共享格式               |
| `runtime.ts`                            | facet 加载、服务提供、热替换和资源清理       | Chord、SDK、归档解压             |
| `service-router.ts`                     | 通过 Chord RemoteServiceSource 连接插件服务  | Chord、插件声明                  |
| `ui-server.ts`                          | 页面令牌、请求校验和插件 UI RPC              | `PluginUi` 接口、串行队列        |
| `src-tauri/src/controller.rs`           | sidecar 进程通信、日志和退出                 | Tauri shell                      |
| `src-tauri/src/desktop.rs`              | 数据目录、窗口和登录启动                     | Windows / Tauri                  |
| `src-tauri/src/tray.rs`                 | 托盘菜单与操作路由                           | 桌面和进程模块                   |
| `scripts/`                              | 插件编译发布和 SEA 打包                      | 共享发布格式、构建工具           |

## 约束

- 页面组件不导入 Tauri、Chord 或文件系统；桌面调用集中在前端适配器。
- `ports.ts` 定义插件生命周期和 UI 的窄接口，UI 服务不依赖具体 Chord 实现。
- 状态属于控制器实例或界面会话；模块导入不启动服务。
- 所有插件状态变更与 UI 调用经过同一队列，避免更新与调用相互穿插。
- 更新前校验签名、身份、版本、哈希和归档；新代激活失败不会替换正在运行的旧代。
- 插件数据目录独立于暂存代码，代码替换和清理不触及用户数据。
- 插件通过 `services.provides`、`services.requires` 声明 Chord 服务；提供者晚到或重载时，消费者句柄自动重绑定。新增业务插件只需发布签名包，不需要修改控制器。
- `hooks` 是通用的宿主操作钩子。插件在自己的服务中处理验证或策略，控制器只传递操作名称和 JSON 输入。
- Windows 壁纸策略属于插件适配器：它备份当前用户注册表值，设置 `NoChangingWallPaper` 与固定 `Wallpaper`，停用时只在值仍由本插件持有的情况下恢复。

## 原生能力与守护边界

`native-bridge.ts` 负责权限检查、请求关联、取消和超时，原生回复直接由 stdio 处理，不排在插件激活/清理队列后。`native/` 只提供当前用户注册表原始值、壁纸路径和进程原语。浏览器名称、密码规则、允许时间、壁纸策略键和值全部留在插件中。主程序和控制器不引用具体插件 ID 或业务服务契约。

`plugin_windows.rs` 负责通用插件窗口；`desktop.rs` 负责桌面操作请求关联与超时；`guard.rs` 负责双进程运行会话及有界恢复；`updater.rs` 负责签名更新。更新通过控制器的停止/恢复接口配合守护，守护会话结束后旧线程先退出，新会话才可开始。副进程响应绑定启动时的 PID，避免旧请求发给已替换的控制器。

缓存插件在启动时先恢复本地版本，不等待 GitHub；随后按配置周期检查更新。首次安装立即同步目录。网络下载仍在控制器的串行更新事务中执行，正在进行同步时的插件 UI 请求可能等待本轮同步完成。

## 界面原则

插件、记录、设置分别承载操作、历史和配置。文案说明当前状态及可执行操作；实现技术、开发模式和发布流程放在开发文档中。空状态、失败原因和按钮的进行中状态只在对应场景出现。

## 测试边界

进程测试验证真实发布源到 Chord 的执行链；浏览器测试从应用装配边界注入通信客户端，实际调用同一个控制器进程和本地插件页面，不替换插件实现。SEA 测试单独验证打包后的运行环境。Windows 安装器、托盘和 WebView2 行为还需 Windows 构建和桌面验证。
